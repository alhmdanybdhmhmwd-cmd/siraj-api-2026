# برق — تسليم إصلاحات المرحلة السابعة إلى المرحلة الثامنة

التاريخ: 2026-11-23  
فرع العمل: `barq/phase8-cleanup-preview-readiness-2026-11-23`  
فرع الأساس: `barq/phase7-integration-audit-2026-11-22`

## قرار الانتقال

بناءً على توجيه المستخدم، يبدأ العمل في المرحلة الثامنة دون انتظار نشر Worker المعزول أو اختبار التكامل الحي للمرحلة السابعة. هذا قرار بتأجيل ذلك الاختبار، وليس إثباتاً لنجاحه. تبقى اختبارات الهواتف الحقيقية مؤجلة إلى مرحلة الاختبارات النهائية، ولا يُعاد تشغيل اختبارات Android البرمجية التي اجتازت CI إلا عند تغيير مؤثر عليها.

## إصلاحات المرحلة السابعة المحفوظة في فرع المرحلة الثامنة

تم إنشاء فرع المرحلة الثامنة مباشرة من فرع المرحلة السابعة، لذلك يرث كل التعديلات الموجودة فيه دون نسخها يدوياً أو إعادة تنفيذها. مواضع الإصلاحات الأساسية:

| الموضع | الإصلاح المحفوظ |
|---|---|
| `api/[...path].js` | تعطيل body parser الافتراضي حتى يصل جسم طلب التسجيل والطلبات الثنائية إلى Worker كما أُرسل؛ حدود أحجام الطلبات؛ تمرير ترويسات SPARK وبيانات الوسائط وRange؛ عدم إعادة محاولات الكتابة غير الآمنة إلا مع idempotency key؛ إبقاء Preview على upstream معزول. |
| `test/proxy.test.mjs` | اختبارات تمرير بيانات SPARK الوصفية ومفتاح idempotency ومدة الرد الصوتي والترويسات عبر proxy. |
| `src/src/media_multipart_routes.js` | مسارات الرفع المجزأ والاستئناف والتحقق من العضوية والقطع وسلامة المحتوى وتنظيف الملفات المرحلية. |
| `test/media_multipart_routes.integration.test.mjs` | اختبارات تكامل معزولة لاستئناف الرفع، ومنع تضارب إعادة الإرسال، والإكمال والإلغاء والتنظيف ومطابقة SHA-256. |
| `wrangler.fallback.test.toml` | Worker احتياطي مستقل للاختبار فقط، مربوط بقاعدة D1 وحاوية Preview وليس موارد الإنتاج. |
| `.github/workflows/barq-preview-fallback-deploy.yml` | نشر يدوي يتطلب موافقة صريحة، ويتحقق من عزل موارد Preview ثم يجري فحوص الصحة وتكامل الحسابات والرسائل وSPARK والوسائط. |
| `.github/workflows/barq-phase7-integration-audit.yml` | إدراج تغييرات سير عمل النشر المعزول ضمن محفزات تدقيق المرحلة السابعة. |

## نتائج المرحلة السابعة التي لا نعيدها

- تحليل Flutter واختبارات Android البرمجية: ناجحة في CI.
- اختبارات Backend وD1 والمخطط وإعدادات النشر: ناجحة في CI.
- لم يُبنَ APK ولم يُنشر أي إصدار إنتاجي.

## ما تم تأجيله صراحةً

- نشر Worker المعزول والتحقق الحي من `/health/live` و`/health/ready`.
- اختبارات التكامل الحي على موارد Preview الحقيقية.
- اختبارات الهواتف والشبكات الفعلية؛ لا تُسجل هذه البنود كنجاح حتى تنفذ لاحقاً.

## حدود السلامة

- لا دمج في `main`، ولا نشر إنتاجي.
- لا تغيير DNS أو توجيه تطبيق المستخدم إلى مزود جديد.
- لا استخدام لقاعدة الإنتاج `siraj-db` أو حاوية الإنتاج `siraj-media` في الاختبارات.
- لا حذف أو نقل بيانات مستخدمين أو تغيير سياسات الاحتفاظ دون قرار واختبارات منفصلة.

هذا الملف سجل تسليم وتتبع فقط؛ لا يغيّر سلوك التطبيق أو إعدادات الخادم.
