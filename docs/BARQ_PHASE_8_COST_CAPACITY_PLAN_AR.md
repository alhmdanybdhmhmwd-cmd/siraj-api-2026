# المرحلة 8 — الخطوة السابعة: التكلفة والتوسع

## جرد الحدود الحالية من المصدر

| المورد/المسار | الحد البرمجي الحالي |
|---|---:|
| مرفقات المحادثات عبر multipart | 60 MiB لكل ملف؛ أجزاء 5 MiB؛ نقل داخلي 1 MiB |
| جلسة الرفع غير المكتملة | 24 ساعة قبل التنظيف |
| صورة الملف الشخصي/الذاكرة | 4 MiB لكل طلب |
| وسائط SPARK | 60 MiB لكل طلب |
| الرد الصوتي على SPARK | 5 MiB |
| التفريغ الصوتي | 2 MiB و10 طلبات لكل حساب في الساعة |
| محاولات الدخول | 10 لكل معرف/عميل في نافذة 15 دقيقة |
| محاولات الاسترداد | 5 لكل معرف في نافذة 15 دقيقة |
| تنظيف المرفقات المنتهية | حتى 100 سجل في دورة التنظيف |
| تنظيف جلسات الرفع | حتى 50 جلسة في الدورة |
| سجل الرسائل | صفحات حتى 50 رسالة للمحادثات الخاصة/المجموعات بحسب المسار |

هذه حدود في الكود وليست حدود خطة المزود أو قياس استهلاك فعلي. لا تعني أن كل المستخدمين يملكون حصة تخزين أو نقل محددة.

## نموذج التكلفة

أضيفت الدالة `estimateMonthlyUsageCost` لتقدير التكلفة الشهرية من قياسات المزود الفعلية، دون تضمين أسعار افتراضية أو ربط BARQ بمزود واحد:

- التخزين: GiB-month × سعر GiB-month.
- نقل البيانات الصادر: GiB المنقولة × سعر GiB.
- الطلبات: ملايين الطلبات × سعر المليون.
- قاعدة البيانات: ملايين القراءات والكتابات × أسعار وحداتها.

كل الأسعار مدخلات من مسؤول المشروع بعد مراجعة فاتورة المزود وعملته وحدود خطته. الناتج تقدير لا فاتورة ولا ضمان سعر.

## سياسة تنبيه الميزانية

أضيفت `evaluateUsageBudgets` لتصنيف الاستخدام لكل من التخزين والنقل والطلبات وقراءات/كتابات قاعدة البيانات:

- أقل من 80%: `ok`.
- من 80% إلى أقل من 100%: `warning`.
- 100% أو أكثر: `exceeded`.
- الميزانية غير المضبوطة: `unconfigured`، ولا تعامل على أنها صفر أو على أنها آمنة.

الدوال لا توقف طلبات المستخدمين ولا تحذف بيانات ولا تضع سقفاً جديداً على الحسابات. هي طبقة حساب وتنبيه قابلة للربط لاحقاً بمصادر قياس المزود ولوحة الإدارة.

## ما يجب قياسه قبل تحديد ميزانيات حقيقية

1. إجمالي التخزين المستخدم فعلياً، والزيادة الصافية يومياً/أسبوعياً.
2. تنزيلات الوسائط بالبايت، وعدد الطلبات، ومتوسط حجم الملف، ونسبة Range.
3. عدد المستخدمين النشطين يومياً وشهرياً، والذروة المتزامنة، ومعدل الرسائل.
4. قراءات وكتابات D1 وحجم قاعدة البيانات ومعدلات نموها.
5. عمليات التخزين (PUT/GET/HEAD/DELETE) وفشلها وإعادة محاولاتها.
6. تكلفة خدمات الذكاء الاصطناعي والتفريغ الصوتي إن كانت مفوترة حسب الاستخدام.
7. مقارنة الاستهلاك مع الأسعار الفعلية والتنبيهات في لوحة المزود.

## قرارات التوسع الآمنة

- لا ترفع حدود الملفات عشوائياً؛ 60 MiB سقف لكل ملف وليس حصة تخزين للمستخدم.
- لا تضف حصصاً يومية أو شهرية للمستخدمين قبل توفر قياسات فعلية وموافقة المنتج؛ لا نريد تعطيل إرسال الصور أو الرسائل دون داعٍ.
- راقب نمو قاعدة البيانات والفهارس ومدة الاستعلامات قبل اختيار خطة أكبر أو نقل قاعدة البيانات.
- اجعل تنبيهات 80% و100% إشعارات تشغيلية للمسؤول أولاً، ولا تحولها إلى منع تلقائي لحركة المستخدمين.
- راجع سياسة الاحتفاظ بالمرفقات الدائمة قبل حساب التخزين طويل الأمد؛ لا تحذف الملفات أو تغيّر سياسة 72 ساعة ضمن هذه الخطوة.

## حدود الإثبات الحالي

اختبارات وحدة الحساب والتنبيه لا تقيس فواتير Cloudflare أو Tigris أو Vercel، ولا تثبت حدود الخطط الحالية. لا توجد بعد بيانات استخدام إنتاجية موصولة بهذه الدوال؛ يلزم مصدر القياس من لوحات المزود/واجهاته وموافقة المستخدم قبل تفعيل تجميع دائم أو لوحة مراقبة. لا تغييرات في D1 أو إعدادات الإنتاج أو DNS أو التخزين.
