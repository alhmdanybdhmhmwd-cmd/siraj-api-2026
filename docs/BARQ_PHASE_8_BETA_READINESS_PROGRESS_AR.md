## أعمال مثبتة في هذا التحديث

1. ورث فرع المرحلة الثامنة إصلاحات المرحلة السابعة من فرعها مباشرة، ووُثق موضع كل إصلاح في `docs/BARQ_PHASE_7_CLOSEOUT_AND_PHASE_8_CARRYOVER_AR.md`.
2. عُدّل `.github/workflows/barq-android-quality.yml` حتى يعمل فحص Android على فروع `barq/**` بدلاً من اقتصاره على فرعين قديمين.
3. أصبح دفع التغييرات وتشغيل Pull Request يشغّل التحليل واختبارات Flutter فقط؛ لم يعد ينتج APK تلقائياً.
4. أضيف مسار اختياري لبناء APK تجريبي داخلي فقط عند تشغيل workflow يدوياً مع `build_beta_apk=true`، وبعد توفير متغيري مستودع HTTPS:
   - `BARQ_API_BASE`: عنوان API الخاص ببيئة Preview المعزولة.
   - `BARQ_MEDIA_BASE`: عنوان الوسائط الخاص ببيئة Preview المعزولة.
5. أزيلت عناوين Preview القديمة المثبتة من خطوات بناء APK؛ لا يمكن بناء نسخة تجريبية موجّهة إلى خادم قديم بالخطأ.
6. يقتصر Artifact على اختبار داخلي لمدة 7 أيام، ولا ينشر إصداراً عاماً.

## ما لا يزال غير مثبت

- لا يوجد Worker مستقل خارج Cloudflare منشور أو متصل بقاعدة اختبار مستقلة؛ adapters الحالية وlibSQL adapter لا تعني أن ترحيل البيانات أو استضافة API البديلة اكتمل.
- لم يُنفذ اختبار حي شامل لـVercel/Worker/Tigris على Preview.
- لم يُختبر الاتصال من شبكات يمنية دون VPN.
- لا تُعد اختبارات CI بديلاً عن اختبارات الجهاز الفعلي أو الشبكات اليمنية.
- لم يُبنَ APK تجريبي بعد، ولم يُنشر أي شيء للإنتاج أو إلى متجر.

## الخطوة التالية

انتظار اكتمال Android quality gate. بعد نجاحه، استكمال جرد فجوات runtime المستقل ومسارات API/الوسائط، ثم نشر Preview المعزول واختباره. لا يبدأ بناء APK التجريبي حتى تثبيت عناوين Preview الصحيحة والتحقق من جاهزيتها.
